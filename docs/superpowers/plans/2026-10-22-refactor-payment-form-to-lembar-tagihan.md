# Plan: Refactor PaymentForm to Lembar Tagihan (Physical Form Alignment)

**Date:** 2026-10-22
**Priority:** P1 (Correctness — current implementation doesn't match client's actual form)
**Status:** COMPLETED (commit `6af0d28`)
**Related Spec:** `docs/superpowers/specs/2026-10-21-weekly-payment-form-design.md` (revised Section 13)
**Related Original Plan:** `docs/superpowers/plans/2026-10-21-weekly-payment-form.md` (superseded in print layout + several fields)
**Related ADR:** ADR-0006 (pre-printed number manual input), ADR-0007 (terbilang zero-dependency implementation)

---

## 1. Context & Problem Statement

### 1.1 Current State
`PaymentForm` entity + `/payment-forms` route + print modal shipped per original Spec #6 on 2026-10-21. However, the design was based on a generic AP document assumption — not aligned with client's actual physical form.

Client provided physical form reference (`LEMBAR TAGIHAN / 请款单` from PT. Brilliant Jaya Wood Industry carbon copy book, serial `N° 018532`) on 2026-10-22. The real form has:

- Pre-printed serial number from carbon book (not auto-generated by system)
- Single tanggal (not date range)
- 6-column line item table with Kategori / Konten / Tujuan / Harga Satuan / Jumlah / Total
- 5 specific signature slots (Manager Umum, Finance, Kepala Akuntan, Kepala Dep., Pembuat)
- Bilingual Indonesian + Mandarin labels
- "Terbilang" field for amount in words
- Company name hardcoded in header

### 1.2 Mismatch Summary

| Aspect | Current Implementation | Physical Form Reality |
|---|---|---|
| Form number | Auto `PAY-2026-W##-...` | Pre-printed `N° 018532` from carbon book |
| Date on print | Week range (Sat-Fri) | Single `issueDate` |
| Line item columns | SKSHHK/kavling/volume/pph/net | Kategori/Konten/Tujuan/Harga/Jumlah+Unit/Total |
| Signatures | Generic 3-slot (Penerima/Bendahara/Mengetahui) | 5 named roles |
| Company name | `AppSettings.yardName` | Needs dedicated `companyName` field |
| Amount in words | None | "Terbilang" (UPPERCASE Indonesian) |
| Language | ID + EN | **ID + Mandarin** (operator reality) |

### 1.3 Why Refactor (Not Deprecate + Rebuild)
- Original PaymentForm entity shipped same day; no production data yet.
- URL `/payment-forms` and nav entry already in muscle memory for operators.
- Status workflow (DRAFT → ISSUED → PAID → VOID) and weekly grouping logic remain valid — only presentation + line item structure change.
- Keeping entity name preserves existing commit history and audit trail.

### 1.4 Non-Goals
- No change to status workflow semantics.
- No change to weekly grouping algorithm (still Sat-Fri, still per supplier × species × contract).
- No addition of approval workflow (signatures remain template-only per Q5=A).
- No separate `LembarTagihan` entity (refactor-in-place, not duplicate).

## 2. Design Decisions Being Implemented

Pulled from Spec Section 13 and client Q&A:

| # | Decision | Source |
|---|---|---|
| 1 | Pre-printed number is **user input**, not auto-generated | Client Q1=A → ADR-0006 |
| 2 | `issueDate` is single date for print; weekly window remains internal metadata | Client Q2 confirmed |
| 3 | Line item structure matches physical form 6-column layout | Client Q3 |
| 4 | Line unit enum: `m³` / `batang` / `rit` / `lain-lain` | Client Q3b=X |
| 5 | 1 form = 1 supplier (unchanged from Spec #6) | Client Q3d=A |
| 6 | Signature slots are template-only, no approval tracking | Client Q5=A |
| 7 | `AppSettings.companyName` for header (default: "PT. BRILLIANT JAYA WOOD INDUSTRY") | Client Q6=B |
| 8 | Terbilang: UPPERCASE + auto-suffix "RUPIAH" + "KOMA" format for decimals | Client Q7a=C, Q7b=A, Q7c=C |

## 5. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Existing PaymentForm records (if any) break during migration | Backfill: `preprintedNumber = ''`, `issueDate = DATE(created_at)`. Document that these records cannot be re-issued until preprintedNumber is manually added. |
| SQLite `ALTER TABLE RENAME COLUMN` requires recent SQLite version | Verify Node.js 22+ bundled SQLite supports it (3.25+). Fallback: create new column, copy data, drop old. |
| Supabase migration ordering with existing deployments | Migration file timestamp ensures correct ordering. Test on staging first. |
| Terbilang implementation bugs for edge cases | Comprehensive test suite in Phase 2 (14+ test cases covering boundaries, special words, decimals). |
| Print layout rendering differences across browsers | Primary target: Chrome (operator standard). Verify in Firefox + Safari. A4 portrait with explicit `@page { size: A4; margin: 15mm }`. |
| Operator confusion between generated internal ID and preprintedNumber | UI label clearly: "No. Kwitansi Buku" for preprintedNumber vs system-only "Form ID" (shown in URL only, not labeled in UI). |
| Deleted `payment-form-numbering` logic needed later | Deletion is intentional per Q1=A. If auto-numbering ever requested again, re-create from git history. |
| Issue date validation breaks existing DRAFT forms | DRAFT forms without issueDate render as "Belum di-issue" with empty date fields awaiting input. Only ISSUED/PAID require valid issueDate. |
